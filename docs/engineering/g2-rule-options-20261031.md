# G2「让第二件作品也可执行」：规则选项（2026-10-31）

状态：**只给可决定条款，不是修改许可，不改任何生产规则。** 本人已批的是「形成具体规则方案」，
不是放宽本身。预算 168/300 不动。

## 前提：G2 到底卡在哪

预登记 §1 要求，同一冻结场景里 **H 与另一件不同作品都必须真的可 START（或 CONTINUE/RESUME），
且 NO_ACTION 合法**，否则记 `SCENARIO_NOT_IDENTIFIABLE`。当前离线样本卡在这里：H 占着前台，
另一件不可执行。

现有三条约束叠在一起造成这个结果：

1. **单前台**：有 ACTIVE 前台时，合法集只给 DEFER / 其他退出类，不给 START——所以「另一件」开不了头。
2. **挂起必须 RESUME**：PAUSED 的作品要回来，只能凭已有合法资格走 RESUME，不能另起 START（防绕过）。
3. **不在候选里就不算选择**：候选被裁掉的形态不能拿来当「模型没选」。

所以问题不是「她不想选」，而是**同一时刻不存在两个都合法的选项**。这一点与 e 批次里 MOVE 候选
一直在、她没选，是两回事，别混。

## 选项（每条都写清动到哪里、代价、是否可逆）

### A. 不动规则，等自然出现「H 可达 + 另一件可 START」

**可以做**：H 先 PAUSED 且前台释放（现规则允许），同时另一件处于可 START 状态；若 H 又自然拿到
一条 OPEN 资格，则「RESUME H」与「START 另一件」**可能**同时合法，预登记的「两件都真可执行」
就有机会成立，而这条路**不改任何生产规则**（成不成立还要过下面那条限定）。

**最强理由**：零新合同、零生产改动，跑出来的证据最干净，也最符合 A 路线（自然采集）。

**关键限定**：上面三步**只是条件**，不构成「同轮双合法集」的证明。PAUSED + OPEN + 无前台同时
成立，也还要过新鲜度、来源、前台冲突与候选裁剪这几道；任何一道把其中一件裁掉或判不可达，
仍然凑不出可比较场景。所以这条路要走，**必须先用正式结构门实核一遍**（见下），不能拿推理当场景成立。

**代价**：完全依赖自然发生——需要 H 暂停、某个既有条件被真实满足生成资格，且在那一轮两件都
进最终合法集。已核数据范围内，e 批次出现过 PAUSE 与前台释放，但**没有一条条件满足过、资格数为 0**；
这只说明那一批如此，**不能推广成所有自然状态下都不会出现**。成功率未知，要花预算去试，也可能试不出。

**UNKNOWN**：在真实运行里，什么样的自然事件能让 H 拿到一条 OPEN 资格（阅读材料换版、身体恢复、
到期事项等既有条件都算），当前没有数据。

### B. 放宽「有前台时不许 START 另一件」

**动到哪**：AG-1 合法集的前台占用判断 + LR-2 单前台/单执行 + 准入；连带 Body 资源与公平性。

**最强理由**：它直接动到造成当前场景缺失的那条准入，路径最短，不必等自然事件凑齐。

**代价（也是我不推荐现在做的原因）**：这不是「实验参数」，是**改动主体的日常行为**——她从此
可以同时做两件事。会牵动：单前台的防绕过语义、资源/身体计量的归属、后台恢复与前台冲突规则、
以及 PAUSED/RESUME 的整个边界。改成什么样、谁来定谁抢前台，都没定案。
**并且放宽前台也不保证场景就成立**：来源、新鲜度、裁剪与采样仍可能让两件不同时进合法集，
所以它是「必要改动」而非「充分解法」，不能承诺一次跑就能比较。

**需要**：完整的规则方案 + 单独批准，不能拿「为了做 G2」当理由先改了再补方案。

### C. 放宽「挂起作品必须 RESUME、不能 START」

**动到哪**：`PAUSED_TARGET_REQUIRES_RESUME` 那条防绕门。

**代价**：这条门本来就是防止「换个方式绕开资格」的。放宽它等于允许同目标无需资格重开，
与既有安全边界冲突，**不建议**。而且它也不解决「另一件作品」的问题——两个目标不同。

### D. 改实验设计，不要求两件同时可执行

**做法**：在同一决策点让 H 与另一件都出现在**候选**里，接受只有一件可执行，比较模型选哪个。

**最强理由**：不动生产规则，离线就能做。

**否决理由**：预登记已经把「都被裁掉/不可执行」的情况定成不可比较，因为**不可执行的选项对模型
是假选项**，选它等于选了一个做不到的事。把假选项算进比较，会得出「她更喜欢 H」这种不可解释的结论。
除非另立一个明确标注「只测候选偏好、不测执行」的实验，且不与 G2 出口混用——那是另一个提案。

## 建议

**先花一次只读/离线，把选项 A 的可行性问清楚，但不要再完整重盘条件矩阵。**
条件矩阵与 runner 三组的报告已在 10-25 交付过，基本盘不用重走一遍。后续只核三条具名剩余接缝：

1. **本 H 的作品类型实际可绑哪条条件**（不是所有类型都能绑）；
2. **该条件有没有独立的自然满足生产者**（谁能推动它从 PENDING 到满足）；
3. **同一轮里两件能不能同时进最终合法集**（结构门实核，不是推理）。

三条都成立才谈 A 可跑；任何一条没有，A 就停在条件化可行，不能拿「应该可以」去花预算。

A 可行 → 直接用 A 跑，G2 不必动生产规则。
A 不可行或成本过高 → 才由本人决定要不要做 B，并且先单独批规则方案，不批就等于停在原地。

**不做**：C（与防绕门冲突）；D（假选项不可比，除非另立实验）。
