# S05 最小 Episode 与摘要来源合同（待批准，未实施）

依据：v2《原文选段 L12169–L12391》Q2、Q27、Q28、Q30。当前已有真实结果→AG-2 handoff→M0 接纳与同结果去重；没有 Episode、episode summary、派生索引或语义 NO_CHANGE 评估。本方案不建表、不改 Memory 写口，不是施工授权。

## 推荐记什么、谁写

**Episode 是 S05 内的分组投影，不是第二个经历 owner。** 最小内容是稳定 episode ID、分组规则版本，以及 `record_id + exact_revision + role` 成员引用；不复制原文、证据或 Activity 状态。一个记录可属于多个 Episode，分组不得多算一条经历或一份独立证据。首版只允许依据已核验的共同 Activity／作品来源提出分组；时间相邻、标题相似只作建议，不推定因果。没有可靠来源就不分组，不为所有旧记录强造 Episode。

**摘要是 S05 接纳的派生 MemoryRecord，不是分组附带的一段权威文本。** 摘要候选必须列出 episode／规则版本、确切成员版本、来源根、可见范围；只有 S05 能核验来源资格、接纳并返回结果。AG-2 仍只交接经历，不直接签发“已记住”或摘要；摘要不认证当前事实，也不反向制造源经历。是否调用模型生成摘要须另有真实调用授权，本方案不包含它。

## 和现有 M0 的关系、哪些属于派生

M0 既有经历、handoff 身份及准入结果保留，不把事件改名成 Episode。新增分组与摘要须作为**明确版本化的 S05 扩展**接入原准入边界，不能往现有字段偷塞新语义。摘要提交须核验并登记完整的成员版本／来源依赖；同一输入和操作身份重投不增记录，成员变化形成新候选，不原地改旧摘要。

Episode 成员关系是可重建投影；摘要、以后可能增加的 embedding／检索缓存是派生物。源被撤回、纠正或资格不可核实时，读取先扣留受影响摘要，不能等后台重算才停用。成员变化后旧摘要标陈旧，不继续当当前结论。若现有治理无法可靠核验依赖，摘要提交与读取必须阻断；不得为做摘要顺手重定义删除权威。首版不做 embedding/index，不把源记录去重当派生失效已完成。

## 旧数据和不做的代价

旧 M0 数据不迁移、不批量重分组、不重新准入。旧记录缺确切来源或 revision 时保持原读法，不自动升级成摘要依据；以后如需补分组，走显式、有界的 backfill，保留原 ID 与治理状态。已删除或当前不可读来源不参与补建。

不做时，来源、交接、准入、去重和逐条召回仍可用；但不能把若干记录可靠地当作一次 Episode，也没有可治理、可追溯的聚合摘要。代价是后来判断更依赖逐条检索，不是“她没有记忆”。

## 拍板范围

推荐批准上述最小来源合同后，再圈定一次完整施工：S05 版本化分组／摘要格式、原准入入口的显式扩展、依赖核验与失效读门、幂等及旧数据兼容；不新增身份体系，不改 Memory 删除／恢复权威，不含真实模型花费。若依赖门必须先改删除治理合同，则停报该差异，不能将本方案批准扩大解释。另一选择是保持现状，继续明确报告这些能力未实现。
