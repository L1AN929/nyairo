# 0.5 收尾功能规格：她自己排一天

写于 2026-10-26。状态：用户已确认方向与范围，监工在核权威字段后实施，未实施。

已确认：义务/自选分型、今天排定的事不被 review/question 挤掉；授权至 2026-10-27 01:00 CST；
若需新的持久格式，先交方案再停，不在实现里夹带；不含真实模型日或其它安全例外。

## 要解决什么

今天那次真实压缩日里，她真实做了两件事（阅读并存下私人事项、后来坐下并完成），
其余窗口选择不动。只读核查证明她**能**自己建未来事项（提案有 later_item 字段、AG1 能存、
cycle 写成 FutureItem、到期会回来）；但她那天有没有被给到这个选项、有没有输出过，历史记录
里没有采集（只留了候选数量，没有名单/种类），因此记 **INCONCLUSIVE**，不能说「没给」或「给了没用」。

另外验出一个确定的问题：一轮里「复习」和「提问」占满两个名额时，无对象的到期事项其机会
进不了源选项与最终请求，事项本身仍 OPEN、到期视图仍可见。这是该布置下的末尾截断，
不证明永久饥饿，也不证明它是那天行为的根因。

所以这个功能不是「给她新能力」，是**让她自己排的今天真的能被执行、也能被看见**。

## 一天里有两类事

用户明确：一天的安排**一部分她不能决定**，比如上学、打工；**一部分她自己决定**。

- **义务**：由外部给定（operator 或世界包），她不能取消、不能自己改期、不能挪到别的日子。
  她决定的是「怎么做、什么时候做、做不做」；没做就如实记录未完成，系统不强迫她完成，
  也不假装完成。义务仍然可以在到期后成为候选，并且同样不被挤占。
- **自选**：她自己排的 0–3 件，可以排、可以改、可以放弃。

两类在数据上必须可区分，不能混成一个列表——手机「今天」页分两栏显示；
排程接口返回时也带类型标记。

## 阶段 0：先定数据合同（未定不施工）

现状里没有「今天排定」和「义务类型」的权威字段和正式生产入口。这两样不是实现细节，
是新的数据合同，必须先定清楚再动排序：

- 义务由谁给、以什么字段表达（operator？世界包？），类型标记怎么落；
- 「今天排定」是 FutureItem 上的字段还是另一条记录，权威读口在哪；
- 两者到期后进候选的路径怎么复用已有的 due→popt 机制。

这一阶段只交方案与字段草案，由用户确认；不在排序实现里偷偷加字段，也不把合同藏到后面的单里。

## 用户能看到什么

打开她手机的「今天」：

- 今天她给自己排了几件事（0–3 件），每件一句话。
- 每件的状态：还没开始 / 正在做 / 做完了 / 没做成（附原因）。
- 今天实际做过、但没排进去的事，单独列一栏，不混进「计划完成」。
- 一天什么都没排，就是空的，不编内容。

## 她这一天怎么走

1. **排**：一天里的第一个决策窗口，如果她有未完成的待办，可以自己挑 1–3 件排进今天；
   也可以选择今天不排（合法，不强制）。义务不由她排，但会出现在今天的义务栏里。
2. **做**：排进今天的事项在到期后成为候选，并且**不被复习/提问挤掉**——今天排定的事优先占位。
3. **结**：做完的记结果；没做成的，记下卡在哪。
4. **收**：一天结束前，没做成的事要么顺延到明天（只顺延一次），要么她自己明确放弃；不无限堆积。

## 明确不做

- 不做日历、不做提醒推送、不做外发消息。
- 不给她「每天必须做几件事」的配额，零排程的一天合法。
- 不改记忆准入、不改默认预算、不动旧实例。
- 不从后台替她排事（operator 仍可建事项，但「今天」这一栏只能是她自己排的）。

## 怎么算做成

一次真实压缩日（新根、真模型、cap 20 内），要能看到这条链：

排了（至少 1 件）→ 当天真的去做了 → 完成或明确失败并留下原因 → 手机「今天」页能读到这三步。

任何一步做不到就记未覆盖，不拿测试绿替代。若不排，也算一种结果，但要能看到「她看过待办、选择今天不排」。

## 拆成三个单

**单 1 · 今天的事优先占位**（依赖阶段 0 的字段定稿）
写集：`components/life/scripts/` 里候选构建与到期供给的既有接缝；新增测试与冒烟。
做成：今天排定的事和今天的义务，在候选里各有一个不被 review/question 挤占的位置；
其余排序规则不变；义务与自选在数据上带类型标记。
验收：反例测试——两个名额被占满时，今天排定的事仍出现在候选与最终请求里。

**单 2 · 排今天的动作**
写集：提案校验与 cycle 写入的既有接缝；新增测试与冒烟。
做成：她可以在决策里把一件待办排到「今天」，排进去就今天到期；排不进去时有具名拒绝原因。
验收：真 owner 链路里出现一条「她排了一件今天的事」，且到期视图能看到。

**单 3 · 手机「今天」页与收尾**
写集：`components/phone/` 与它的测试；`GET /api/phone/today` 扩展。
做成：返回排程列表（义务/自选分栏）+ 每件状态 + 未排但做过的事；一天结束时给没做成的
顺延或放弃的入口（只顺延一次）。
注意：这一单**不是纯只读**——顺延/放弃会写状态，属于可见行为，验收要覆盖写入路径与幂等。

## 风险

- 单 1 动的是候选排序，属于产品可见行为；只在「今天排定」这个子集里调优先级，不全局改名额。
- 单 2 可能触碰提案 schema；若需要新增持久字段，停下来先问，不擅自加。
- 单 3 只读扩展，风险最低。
