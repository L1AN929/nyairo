# v0.5 她自己排一天：日计划、外部义务与今日预留位

日期：2026-10-26。范围：在已批准的离线边界内实现「她把既有待办排进今天」「外部义务由 operator
定义、Life 只读」「两条今日预留位不被 review/question 挤掉」以及「结果只从真实 owner 回执投影」。
没有真实模型日、没有访问旧实例、没有新增 MISSED/日终顺延/学校动作。

## 能力

一天有两类安排，数据上严格分开：

- **自选**（她自己的）：`life_day_plan.json`，`chiyo.life.day_plan.v1`。一条记录只引用一个既有的
  `fitem:`、业务日和提交它的 Decision；标题/到期仍由 `life_future_items` 持有，不复制正文。
  一天最多 3 条，0 条合法；只支持「排今天」，不支持日历或未来日。
- **义务**（外部给的）：`life_day_obligations.json`，`chiyo.life.day_obligations.v1`。**只有**
  `scripts/own_day.py` 的 operator 入口能写；Life 拿到的是 `life_day_obligations.DayObligations`，
  这个类没有写方法。义务必须绑定一个现场可读、可续写的 `artifact:` 目标和一个完成依据
  （`ARTIFACT_STEP_RECEIPT`，同一目标、`SUCCEEDED`）。

业务日由注入的业务 clock 按 **+08:00** 换算（与手机 today 同一日界）；安全预算、lease、权限仍走
真实 UTC。旧实例不迁移：两份文件都不存在时行为与以前逐 ref 相同。

## 格式与合法例

计划（Life 自有）：

```json
{"schema_version": "chiyo.life.day_plan.v1", "revision": 1,
 "entries": {"plan:8f2c...": {
   "plan_ref": "plan:8f2c...", "date": "2026-11-10", "class": "SELF_PLANNED",
   "item_ref": "fitem:c272...", "status": "PLANNED", "source": "SUBJECT_DECISION",
   "decision_ref": "dec:...", "revision": 1}}}
```

义务（operator 写，Life 只读）：

```json
{"schema_version": "chiyo.life.day_obligations.v1", "revision": 1,
 "entries": {"oblig:41a0...": {
   "obligation_ref": "oblig:41a0...", "date": "2026-11-10",
   "title": "上午先把导言读完并写一句", "due_at": "2026-11-10T10:30:00+00:00",
   "status": "PLANNED", "source": "OPERATOR", "source_ref": "operator:2026-11-10",
   "target_ref": "artifact:5c42...",
   "completion": {"kind": "ARTIFACT_STEP_RECEIPT",
                  "target_ref": "artifact:5c42...", "expected": "SUCCEEDED"}}}}
```

决策里的排今天的唯一形状是 `plan_today: {"item_ref": "fitem:..."}`；日期不是模型输入。合法例：

```json
{"decision": "NO_ACTION", "selected_candidate_id": null,
 "reason_codes": ["NO_ACTION_CHOSEN"], "short_rationale": null,
 "deferred_candidate_ids": [],
 "plan_today": {"item_ref": "fitem:c2726f0e2244f5d8"}}
```

## 权限与门

- 计划写只发生在 Decision **提交之后**；写失败/日期不是今天/事项不是 OPEN/主体不符/当天已满 3 条
  都具名报告，不静默排程。
- 同一 Decision 幂等；新 Decision 点名同一事项同一天不多建。取消/改期仍走既有
  `future_item_actions`，计划只投影成 `ABANDONED`/不再到期，不写回、不加终态。
- `future_item_actions` 现在只接受 `fitem:` ref；`oblig:` 或别的 owner 命名空间具名拒绝
  （`FUTURE_ITEM_ACTION_REF_NOT_AN_ITEM`）——她不能借这条动作取消义务。 这次收紧没有改变原合法
  输入：裸 id 仍按原规则补成 `fitem:`，`fitem:` ref 原样接受；旧 `FutureItems` 持久记录本来就是
  `fitem:`，取消/改期重读照常；旧 Decision 里若已存下当年规范化后的 `fitem:oblig:...`，重建仍
  通过。 被提前拒绝的只有“本来就会拼成 `fitem:oblig:...` 再去 `NOT_FOUND`”的其它 owner 引用，
  不是任何原本成功的写入。
- 义务导入必须现场校验目标（实例的 Supply 读口）；未知/不可读/不可续/完成依据指向别的对象都拒绝。
  Life 不因「同一作品有历史版本」就报完成：只有当轮真实 owner 回执 `APPLIED` 且目标一致才投影
  `DONE`，否则 `PENDING`/`UNKNOWN`，operator 文档一个字节都不改。
- 预留位仍过既有门：目标已 PAUSED/WAITING → `PAUSED_TARGET_REQUIRES_RESUME`，不因「今天的义务」
  额外 START；没有义务可执行就空位，不造兜底。

## 候选接线

`life_project_options.build_options(..., reserved=[...])` 先按原顺序构造 review → question → due 并
截到 `limit`（默认 2，一字不改），再把两类预留位追加到末尾；有效上限是 `limit + 2`。预留位带
`kind=TODAY_SELF_PLANNED|TODAY_OBLIGATION`、`basis_ref`（`plan:` / `oblig:`）、`work_ref`（真实
`artifact:` 目标或空）和 `dedupe_refs`。选中带 `work_ref` 的预留位 = 继续**它自己绑定**的作品
（不是新建项目）；没有 `work_ref` 的自选仍按普通项目选项处理。

去重不只在 `build_options` 内部：`ArtifactContinuationSource` 在**最终 AG-0 候选**这一层再按
“同一个真实可执行目标 + 同一个继续动作”折叠一次。已存正式反例里，`TODAY_OBLIGATION` 绑定
`seed_artifact` 的同时，普通 artifact continuation 也对同一对象给 START。现在保留带义务标签和
`oblig:` ref 的那一条，丢掉等价普通入口；`closeout:` 是另一个合法动作，仍保留；别的目标、别的
动作也仍在。折叠只认预留位明确给出的 `work_ref` / `dedupe_refs`，不按 `artifact_id` 全局删候选。

处境指纹（`life_step_readiness.SITUATION_KEYS`）新增 `day_plan` / `today_obligations`：计划或
预留集合变化 = 新处境（可以再被问）；同一集合继续安静。未到期的「稍后」列表**不**进指纹——
它还不是她能开工的东西，把它放进去会让每次提案都多花一次请求，破坏既有有界安静。时间流逝本身
不改变指纹；计划只在事项自己到期后供给预留位。

## 实测

WSL，cwd `/mnt/d/nyairo-rc1-body-backend`：

```
PYTHONDONTWRITEBYTECODE=1 /tmp/rc104-venv/bin/python -B \
    -m unittest -q tests.test_v05_own_day          # Ran 58 tests, OK
PYTHONDONTWRITEBYTECODE=1 /tmp/rc104-venv/bin/python -B \
    scripts/v05_own_day_smoke.py                   # SMOKE_OK, checks=15
```

冒烟用隔离真 Supply owner、真 M0 Memory、research/practice/project gateway、真实 private items、
`AutonomousLifeCycle` + `AutonomousLifeRunner`、AG-0/AG-1 原始 JSON/AG-2/AR-0；只有 Decision 回答
与内容回答是脚本替身。实际观察到的正式链：

1. 正式 Decision 建普通 fitem，再以 `plan_today` 排进今天；计划文件 1 条 `PLANNED`、
   `source=SUBJECT_DECISION`，事项仍 OPEN；无字段回合写 0 条。
2. operator 入口拒绝不存在的目标（具名 `OBLIGATION_TARGET_UNREADABLE`），合法义务写一次、重放
   不建第二条；Life 侧 reader 是 `DayObligations` 且没有写方法。
3. 两个 question 选项占满 2 个常规位，今日自选 + 义务两条预留仍进入最终请求（共 4 条），两条
   `popt:` 候选 `legal_decisions` 均含 START；该回合 NO_ACTION 计划/义务/作品零写。同一回合的
   最终候选里，绑定 `seed_artifact` 的可执行入口只剩义务 `popt:` 一条，普通 artifact continuation
   被折叠；同对象的 `closeout:` 仍在，另建的第二件作品仍各自有 continuation 候选。
4. 另一次正式的 START 选中义务预留位：AR-0 走真实 owner，版本 +1，回执 `APPLIED`，义务结果投影
   `DONE` 且绑定同一 `decision_id`；随后 ABANDON/重复回合不再写版本或义务文档。
5. 取消/改期经真实 `future_item_actions` 生效后预留位撤回、计划投影 `ABANDONED`；义务文件损坏 →
   `READ_FAILED` + `OBLIGATIONS_STATE_CORRUPT`；目标归档 → `OBLIGATION_TARGET_NOT_EXECUTABLE`；
   目标 PAUSED → `PAUSED_TARGET_REQUIRES_RESUME` 且同目标没有额外 START。同根新存储实例重读计划
   内容一致、文件未变。
6. 义务真实一步成功（AR-0 Action `SUCCEEDED`、owner 回执带版本）后，关闭原 runtime、排空 Supply
   服务，再**同根新装配**：新 cycle 不做任何执行就先把该义务投影为 `DONE`，证据里的
   `decision_id` / `action_id` / `activity_ref` / `version_id` 与关闭前那次真实 step 完全对应，
   `evidence_path=PERSISTED_ACTION_RECEIPT`；operator 义务文件字节不变、作品 head 不变、Action 数
   不变，义务不再作为可执行预留位或候选出现。 这条链只重读已有的 Action/Decision/owner 回执，
   没有新增结果 store 或 sidecar。

## 未验证 / 边界

- 没有真实产品模型日，不证明她自然采用 `plan_today`，也不证明「完整一天」。
- `DONE` 的同根重读只验证“同一实例、同一 PID 的有序关闭/重装配”，不是 crash、强杀、半写或跨 PID
  恢复；Action/Decision/owner 回执的读取失败会投影 `UNKNOWN`，不伪造 `DONE`，也不会把一次
  `UNKNOWN` 当成可安全重放的 `PENDING`。 它仍然只说明“这一条义务的那一次真实 step 已被记住”，
  不证明内容质量或她第二天还记得。
- 关联依赖 AG-0 给预留位候选的确定性 id：Decision 存的是 candidate id，不是 `popt:` 载荷本身。
  如果源种类或候选 id 公式将来改变，旧结果会诚实地落到 `UNKNOWN`，不会误认成 `DONE`。
- `UNKNOWN` / 其它目标 / 其它 Decision / 未知关联的负控在单元测试里覆盖，走的是假的 Action/
  Decision/回执读口，不是真实故障注入。
- 手机「今天」页、跨日计划、World 日界（Asia/Tokyo）转换、义务取消/改期（本来就不允许）都不在
  本单范围。
- 义务目标校验是现场 Supply 读；真实撤权/不可读故障只用隔离夹具覆盖，未在旧实例上演练。
