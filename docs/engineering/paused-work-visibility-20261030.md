# 挂起的作品会不会再被想到：本次只读结论

**有恢复路径，但没有“因为没做完就自动回头”的通用保证。** 这次只核现树8个命中文件、3篇已交决策和b批已有安全导出，没有跑测试、模型、服务或读取已结束实例。

PAUSE释放前台后，它不再由CURRENT_ACTIVITY当作正在做的事供给。已核的正式恢复路径是：模型显式选择已提供的条件 → owner核实满足 → OPEN资格 → 有效搁置候选 → 新Decision自选RESUME。无条件PAUSE本次不建条件、不发资格；条件一直未满足，也不会仅因事情没做完就自动发资格。明确自选时刻是已有条件，不等于系统默认计时器；条件过期也不是自动恢复。以上限扫描范围，不宣称所有未来显式操作都不可能改变它。

已有“有效搁置供给”补的是有合法资格时能在静默门之前成为材料；“条件PAUSE”补的是资格如何依法生成；“多挂起单执行”允许放下A做B，但另一件正在执行时不能抢占。它们不负责默认提醒、未完成吸引或无资格重新考虑。同目标作品的既有续作/额外机会源还会过滤PAUSED/WAITING，防止新START绕恢复门。

候选没有本次核到的未完成作品专属优先权。报告定位到的默认界限是单源25、全局100、最终prompt最多16条及12000字符；去重后的总排序按candidate_id字典序，不是按价值或新近度排名。实际参数可能由装配决定。有效资格只是获得供给机会，不保证避开各级裁剪或保证模型看到。

另一个区别：continuity读面能把PAUSED列作unfinished材料；worker定位到它与可执行RESUME对PAUSED的标记存在静态差异。但该材料是否进入本次模型最终视图、差异是否影响行为未核，不能称已证生产缺陷，也不自行修规则。

**今天b批的历史问题仍有证据缺口。** 已有导出证明A首轮START、后续第23轮PAUSE，原A没有后续版本；不是“后续再无A记录”。b批共3个PAUSE，第四件最后START成功但未记录PAUSE。已有导出没有完整候选名单/顺序、最终候选呈现、PAUSE hint、条件状态和资格记录。因此A后续在不在候选、排第几、是否被模型看到，以及有没有满足条件，均是UNKNOWN；不能从选择别的作品倒推没供给，也不能把reason code当执行模式证明。

父级只做JSON字段、引用路径及已有导出计数核对，发现并修正A后续记录0→1、收窄“有效资格必展示”“无任何未来路径”等过强推断。没有重跑行为验证。产品新增0，保守121/300不变；本批G1仍未覆盖，不新开运行或新增提醒、timer、优先级、资格规则。要追现场证据，最小缺少的是逐轮候选IDs/来源/可用状态、实际送入模型的候选IDs，以及条件/资格IDs和状态，而不是全文prompt或私人内容；本次没有追加读取或采集。
