# V-C：恢复不复活的短方案

状态：方案主体未实施；2026-10-26 只落地其中的最小保留底账与当前性交接（见文末“本轮限定实现”）。
历史旧evidence与旧controls一起恢复会让正文复活，**整体V-C仍FAIL**，不承诺抵抗整机回滚。

## 建议怎么做

把最新删除/纠正事实保存在**业务备份还原流程无权回滚的控制权威**中，现有controls仍作为本地治理投影。恢复先取得可信、足够新的控制记录，再补齐扣留并开放读取；取不到或无法证明完整，就具名阻断相关Memory读取，不把故障说成空记忆。

推荐独立管理的在线控制服务。实际主机、账号、存储及备份权限尚未落实，这些是部署前提，不是假定已有的设施。同机换目录不算域外；独立账号也不能抵抗拥有整机权限的管理员同时回滚两边。权威本身也回滚、独立记录丢失等情况不在防复活保证内，必须阻断，不能自证最新。

离线记录可作替代，但必须有一条可信流程确认覆盖全部已成功控制操作。**签名只能证明谁签过，不能单独证明这是最新头**；没有这种覆盖证明，离线头不能用来放行恢复。

## 保存什么、谁来写

只保存控制元数据，不保存正文：Memory owner、conversation、稳定event目标、DELETE/CORRECT及replacement引用、operation_id幂等键、控制来源/批准记录引用、权威序号、writer世代和审计时间。时间只用于审计，不作为新鲜度证明。

既有控制入口验证明确控制请求后，先提交权威，再应用本地controls；两步完成才报告成功。权威已提交但本地失败时保留未完成状态，重试复用原幂等键并补投影。writer资格由权威发放，旧writer晚到拒绝。具体本地投影字段和接线留待实施时确定，不为这份方案另造日志或结果域。

## 恢复和旧实例

恢复副本先隔离；核身份、控制记录完整性及足够新证明，补齐最新扣留，再开放read/list/context及已接入的Life/手机读取。来源不可得、记录缺失或无法核实，返回具名BLOCKED且不返回正文。可核实未删的经历仍应能读，不用全部拒绝冒充修复。

旧实例缺权威记录不代表没有删除历史。旧ledger能提供其中保留的事实，不能证明历史完整；空基线或管理员确认也不能把未知删除变成“没有”。未解决的范围继续阻断，本方案不迁移旧实例。缓存及派生面的完整覆盖未核，不承诺全仓删除或收回已经外发的内容。

## 实现时看什么结果

只验证直接关系到本缺陷的路径：只退正文仍扣留；正文与本地controls同时退回但权威保留新删除时仍扣留；权威不可得时具名阻断；同场景未删经历可读。另核旧writer确实被拒。以上均未运行，不为方案预建测试矩阵。

## 留下的决定

实施前只需确定**独立控制权威的实际部署与管理边界**，以及接受“权威不可得时删除不能报告成功、相关读取受限”的可用性代价。旧实例暂不接入；没有可信完整控制历史就不激活对应恢复范围。

本方向到此收口，不自动施工。Memory准入、默认预算、旧实例及外发均不动；0产品新增，共同94/300、余206。下一主线回到作品/实践结果进入后续判断，而不是继续扩V-C细节。

## 本轮限定实现（2026-10-26）

只落地“删除决定放在业务回滚域之外 + 当前性必须显式交接”这一小块，没有恢复状态机、没有独立服务、没有旧实例迁移。

- **位置**：`enable-instance-memory` 不再把底账默认建在实例 `memory/` 里。必须显式给
  `--authority-db <path>`，且路径要在实例业务根之外；落在实例根内会被
  `MEMORY_AUTHORITY_PATH_INSIDE_INSTANCE` 拒绝。该文件只是脱离**实例**备份/还原集，
  **同机换路径不等于抵抗整机回滚**。
- **谁保管、当前性谁维护**：文件由操作者保管。受信下限由正常删除流程自己维护：新建空库在底账旁
  保留 `<authority>.floor.json`（seq 0），之后每次 DELETE 在 append 落库前先推进它；操作者不需要
  每次删除后手改数字。可选的 `NYA02_MEMORY_AUTHORITY_MIN_SEQ` 仍作为交接值，生效下限取文件与它
  的较大值。当前状态用
  `python components/native/memory_authority.py --db <path> --owner <owner> --conversation <conversation>`
  查看，输出 `seq` / `trusted_floor` / `floor_source` / `head_digest`。既有库缺可信历史时不会被
  初始化成 0；只有文件原本不存在且为空库才写零基线。下限文件与底账同域，同域整体回滚不在承诺内。
- **链只证一致性**：哈希链完好只说明文件内部自洽，不说明它是最新副本。读到的头 `seq`
  低于生效下限 → `MEMORY_AUTHORITY_OLDER_THAN_TRUSTED`；没有交接、下限文件不可读/不可写或
  格式坏、下限记录的链摘要与副本不符 → `MEMORY_AUTHORITY_CURRENTNESS_UNPROVEN` /
  `MEMORY_AUTHORITY_HANDOFF_INVALID`。以上都阻断 read/list/context 与新 DELETE，不把旧副本
  当“没有删除”。
- **兼容**：没有配置底账的旧实例仍走原路径，不自动纳管、不迁移、不改其配置。

演示只跑 `scripts/vc_recovery_demo.py`：正文单退/两库同退仍扣留、底账未被业务恢复改写、
删除之后的新经历按原规则可读、旧副本/无交接具名阻断、底账不可得时读取与新删除阻断。
