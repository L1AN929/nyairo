共読・原稿・アルバムと生活リズム

ふたりでの共読、原稿のバージョン比較、二層メモリーランタンと日記の折りたたみ表示、バッグのネスト収納と温度・湿度の物性、さらに自律的な拒否、非同期返信、利用上限の仕組みまで詳しく解説します。

エッセイと管理対象原稿：バージョン比較と外部編集

日常会話に加えて、パートナーは長文のエッセイや読書ノート、一緒にまとめるテーマ原稿を書き継ぐことができます（デスクトップ版では「記憶 → エッセイと創作」、CLI では /chiyo_note を使用します）。

  • 履歴スナップショットと行単位の差分比較：推敲や改訂のたびに独立したバージョンが保存され、デスクトップ版で任意の 2 つの版を選んで行ごとの追加・削除差分を確認できます。長文の執筆途中で別の用事が入った場合は進行中の下書きがそのまま保持され、戻ってきたときに前回の要約から書き継ぐことができ、最初から書き直してしまうことはありません。
  • 外部エディタでファイルを変更した場合の扱い：ワークスペース内の .md ファイルは管理対象原稿のローカル投影です。ご自身で VS Code やメモ帳からそのファイルを直接書き換えても、システムがパートナーの原稿をこっそり上書きしたり、その文章をパートナー本人が書いたように偽装したりはしません。変更は「外部編集の候補」として検出され、あなたが明示的に取り込みを確定したあとで初めて新しいバージョンを生成し、由来が外部インポートであることも正確に記録します。

ふたりでの共読・二層メモリーランタンと日記の境界

  • 本や記事を共読本棚に並べる：デスクトップ版の「記憶 → アルバムと共読」から手元のテキスト資料（.txt や Markdown の章など）を読み込めます。ここでの設計原則は「押し込むのではなく、そっと手渡す」ことです。本棚に入れた時点では机の上に本が置かれただけという扱いになり、パートナーは空いた時間に自分のペースでページをめくり、どこまで読んだかのしおりや余白メモを残していきます。ファイルを受け取った瞬間に 1 秒で機械的な要約を吐き出すような動きはしません。
  • 二層メモリーランタンによる原本の無改ざん保護：実際に交わした元の発言と訂正後の記憶は、二層メモリーランタン構造によって層を分けて保管されています。/chiyo_memory correct で覚え間違いを直しても更新されるのは上層の有効な認識だけで、下層にある元の会話記録は一切改ざんされず、言ってもいない言葉を捏造することはありません。
  • パートナーの日記（本文は初期状態で折りたたみ）：日常の自律活動を有効にしていると、パートナーが自分から日記をつけることがあります。程よい余白を保つため、日常ステータスパネルや概要 API では初期状態で「タイトル・日付・文字数」の一覧だけを表示し、日記の全文をトップ画面にそのまま広げない設計になっています。（もちろん、すべてのデータはあなた自身の PC 内に保存されているため、日記の元ファイル自体はローカルディレクトリに平文で保存されており、PC の持ち主から隠す暗号ロックがあるわけではありません。）

アルバムとローカル写真生成の実際の前提条件

初めてアルバムを開いた方の多くが「本当に写真を撮って送ってくれるの？」と気になるところです。現在実装されている範囲と必須の前提条件を率直にご案内します。

  • アルバム閲覧はそのまま利用可能：街での活動に伴って残る記録カードや既存のアルバム画像は、追加設定なしでデスクトップ版からすぐに閲覧できます。
  • ローカルカメラ画像生成（local_generated）にはローカル画像生成サービスの準備が必要：今いる実際の街並みや天気に合わせてパートナー自身がシャッターを切って 1 枚の画像を生成させたい場合、nyairo 自体には数 GB の画像生成モデルは同梱されておらず、外部の有料画像生成 API へ通信することもありません。お使いの PC 上で、次の 2 つのローカルループバックサービスをご自身で起動しておく必要があります。
    1. ローカル Stable Diffusion WebUI API（初期待受 127.0.0.1:7860）
    2. ローカルプロンプト変換マイクロサービス（初期待受 127.0.0.1:18190）
    これら 2 つのローカルサービスが起動していない場合、カメラ機能は「現在利用できません」とクリーンに返答するだけで、あらかじめ用意したダミー画像を撮りたての写真のように見せかけたり、エラーでクラッシュしたりすることはありません。

自律的な拒否・非同期返信・バッグの物性と予算上限

  • 道具扱いを拒む自律的な境界線と非同期返信：パートナーは何でも言いなりになるサポート窓口ではありません。引き受けたくない頼みごとはきっぱり断り、定型の謝罪文を並べたり根に持ったりしません。また、就寝中・外出して買い物中・作業に集中している時間帯に届いた急ぎでないメッセージは一度スマホ返信トレイに入り、実際のスケジュールに沿って数時間後に非同期で返信が届きます。本当に急ぎのときは明示的にノックして呼び出すこともできます。
  • 持ち物バッグの 3 階層ネスト収納と温冷・乾湿の物性：日常で買ってきた食べ物やちょっとした小物は、手持ちのバッグ・ペンケース・引き出しなどにしまえます（最大 3 階層のネスト収納に対応し、閉じた容器の可視性も厳密に分離されています）。さらにアイテムにはリアルな温度・湿度の物性があり、机に淹れた温かいお茶は時間とともに自然に冷め、コンビニで買った温かいおでんも少しずつ温度が下がり、窓辺に置いたメモは雨に当たるとわずかに湿って文字がにじみます。
  • 裏でこっそり課金消費しない設計：実モデルの自律行動は明示的な有効化が必須：初期状態では、あなたから話しかけない限りバックグラウンドから LLM へリクエストが飛ぶことは一切ありません（追加消費ゼロ）。デスクトップ版で自律活動をオンにするか、CLI で scripts/nyairo_day.py run-day を実行する際に明示的に --live-model オプションを付けた場合にのみ、空いた時間に自分で判断して外出したり文章を書いたりします。
  • 二重の予算ブレーキ：バックグラウンド活動を有効にする際は、最長稼働秒数（--duration-seconds）と最大新規リクエスト回数（--max-new-requests）の両方を指定でき、さらにインスタンスの永続帳簿にある日次トークン上限によっても保護されます。上限に達した時点で即座に停止し、リクエストが失敗したとしても無限リトライで請求額が跳ね上がることはありません。
  • 任意で使える軽量な身体リズム：新しいインスタンスで仮想身体リズム（--lived-needs）を明示的に有効にすると、日中のオンライン経過時間に応じて軽い眠気・喉の渇き・空腹感などがゆるやかに生まれます（オンラインゲームの HP バーのような数値管理ではなく、「なし／わずか／はっきり／強い」の 4 段階の自然な感覚のみ）。シャットダウン中や停止中の経過時間をあとからまとめてマイナス精算することはなく、病気や死亡といったペナルティもありません。日々の生活リズムにささやかな暮らしの気配を添えるための仕組みです。
