Telegram・QQ との連携

Telegram ボットまたは QQ 公式ボット経由で手元の PC 上のパートナーと接続します。認証情報を設定したのに返信が届かないトラブルを防ぐため、セッションホワイトリストの許可設定を必ず確認してください。

Telegram · ボットの作成と Token の設定

外部チャットアプリを設定する前に、まずローカルのターミナルまたはデスクトップ版でモデルから正常に返信が返ってくる状態を確認しておくことをおすすめします。

  1. Telegram 内で公式の @BotFather を検索し、/newbot を送信して案内に沿って新しいボットを作成します。発行された HTTP API Token をコピーしてください（この認証情報はボットの鍵そのものですので、公開グループに貼ったりスクリーンショットに写り込ませたりしないよう厳重に管理してください）。
  2. ターミナルでゲートウェイ設定ウィザードを実行します（Windows デスクトップ版をお使いの方は、「設定 → モデルとチャネル」画面から直接入力することもできます）。
bash
nyairo gateway setup

Telegram を選択し、先ほど取得した Token を入力します。「アクセスを許可するユーザー（Allowed Users）」欄には、ご自身の数字のみの Telegram User ID だけを入力してください（@ユーザー名 や表示名ではありません）。ウィザードが Detected your Telegram user ID を自動検出した場合は、数値に誤りがないか確認してそのまま確定してください。

Telegram · 個人チャットの記憶アクセス権限を紐付ける

見知らぬ第三者がボットへ誤って話しかけ、あなたのプライベートな記憶を読み出してしまうのを防ぐため、nyairo では「どの個人チャットセッションに長期記憶の読み書きを許可するか」を明示的に指定する必要があります。

1 行コマンドの標準インストール（データは ~/.nyairo に保存）をご利用の場合は、以下のスクリプトを実行して画面の案内に従い数字のみの User ID を入力すると、対応するセッション識別子が算出されます。

bash
REL="$HOME/.local/share/nyairo/releases/v0.7.0"
PYTHONPATH="$REL:$REL/vendor/hermes" "$REL/vendor/hermes/.venv/bin/python" -c '
from gateway.config import Platform
from gateway.session import SessionSource, build_session_key
uid = input("Telegram の数字のみの User ID を入力してください: ").strip()
source = SessionSource(platform=Platform.TELEGRAM, chat_type="dm", chat_id=uid, user_id=uid)
print("以下の紐付け用識別子をコピーしてください：")
print(build_session_key(source))
'

算出された識別子をコピーし、~/.nyairo/chiyo/config.json を開きます。

bash
nano "$HOME/.nyairo/chiyo/config.json"

ファイル内の他のフィールドはそのまま残し、gateway_bindings 内の telegram 配列に先ほど算出した文字列を設定します（Windows デスクトップ版をお使いの場合は、「設定 → モデルとチャネル」画面下部にあるセッションホワイトリストからチェックを入れて許可するだけで済みます）。

json
{
  "gateway_bindings": {
    "telegram": ["先ほど出力されたセッション識別子を貼り付け"]
  }
}

Telegram · ゲートウェイの起動と動作確認

保存してエディタを閉じたら、ゲートウェイを起動してオンライン状態を維持します。

bash
nyairo gateway run

同一のボット Token に対して、同時にポーリング受信できるゲートウェイプロセスは 1 つだけです。もし 409 Conflict エラーが出る場合は、ゲートウェイが二重に起動しています（例：デスクトップ版の裏のゲートウェイと手動ターミナルの両方が動いているなど）ので、どちらか一方を終了してください。

スマホの Telegram から自分のボット宛てにメッセージをいくつか送って動作を確認しましょう。

  1. 普段どおりの挨拶を送り、問題なく返信が届くことを確認します。
  2. /chiyo_status を送信し、モジュール状態（Memory: READY）が返ってくることを確認します。
  3. /chiyo_memory list を送信し、個人チャットの記憶アクセス権限が正しく紐付いていることを確認します（新規環境でリストが空と表示されるのは正常です）。

QQ 公式ボットの連携と必ず確認すべき 2 つの注意点

基盤のゲートウェイには QQ 公式ボット（API v2）アダプタが内蔵されています。QQ の個人チャットでパートナーと話したい場合は、QQ オープンプラットフォーム (q.qq.com) でボットを作成し、AppID と AppSecret を取得してください。Windows デスクトップ版の「設定 → モデルとチャネル」にある「QQ 連携」欄へ入力して保存すると、ゲートウェイが自動で再起動して接続を試み、ゲートウェイログから取得した実際の接続結果が画面上にそのまま表示されます。

設定ファイルを手動編集する場合や、「接続できたはずなのに返事が来ない」という場合は、実機検証で判明した次の 2 つの落とし穴を重点的に確認してください。

  1. 設定キー名は必ず qqbot にし、qq と書かないこと：config.yaml の gateway.platforms 配下におけるプラットフォーム名は厳密に qqbot です。誤って qq と手入力すると、ゲートウェイはこの設定ブロック全体をそのまま無視し、ログにエラーすら出力されません。
  2. AppID とシークレットを入力するだけでは不十分で、対象の個人チャットセッションをホワイトリストへ追加する必要があること：nyairo のプライバシーゲートは、gateway_bindings.qqbot で明示的に許可された個人チャットキー（形式は agent:main:qqbot:dm:あなたのユーザー識別子）のみを通過させます。ホワイトリストへ追加する前は、QQ のメッセージがゲートウェイに届いていても静かにブロックされます。まずはボット宛てにひと言メッセージを送ってから、デスクトップ版の「話しかけを許可する相手」パネルで新しく現れたセッションにチェックを入れる（またはログから該当キーを書き写して chiyo/config.json に追記する）ことで、正常に会話できるようになります。

その他のチャットプラットフォームについて

  • 個人版 WeChat（いちばん手軽）：オープンプラットフォームへの登録や複雑な ID 入力は不要で、スマホの WeChat で QR コードをスキャンするだけで接続できます。詳しくは前の章 WeChat 連携 をご覧ください。
  • Feishu（Lark）/ WeCom（企業向け WeChat）/ Discord など：基盤ホストのコードベースには一部サードパーティプラットフォーム向けファイルが残っていますが、記憶アクセス権限の紐付けや切断時の再接続に関する実機検証をまだ完了していないため、現時点では正式サポート対象外としています。
