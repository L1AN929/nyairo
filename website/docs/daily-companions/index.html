共读、文稿、相册与节律

详细介绍双人共读、文稿版本对比、双层回忆灯与日记折起、随身包袋嵌套与冷热物态，以及自主拒绝、异步回信与额度控制。

随笔与受管文稿：版本对比与外部编辑

除了日常对话，TA 还可以维护长篇随笔、读书笔记或你们一起整理的专题文稿（桌面端位于「记忆 → 随笔与创作」，命令行可用 /chiyo_note）：

  • 历史快照与增删对比：每次修订都会留存独立版本，你可以在桌面端直接点选任意两个版本查看逐行增删对比；如果一篇长文写到一半去忙别的事了，手头进度会挂起保留，回来时顺着上一版摘要接着写，不会从头重写。
  • 你在外部改了文件怎么办：工作区里的 .md 文件是受管文稿的一份本地投影。如果你自己用 VS Code 或记事本直接改了这份文件，系统不会悄悄拿它覆盖 TA 的原稿，也不会假装那段话是 TA 自己写的——它会把改动识别为「外部编辑候选」，等你明确确认导入后才生成新版本，并如实注明来源为外部导入。

双人共读、双层回忆灯与 TA 的日记边界

  • 把书或文章放上共读书架：你可以在桌面端「记忆 → 相册与共读」里导入本地文本材料（如 .txt 或 Markdown 章节）。这里的设计原则是「递给 TA，而不是强塞给 TA」——放进书架只代表桌上有这本书可读，TA 会在合适的闲暇节奏里自己翻阅、记下读到哪一页和批注感受，而不是收到文件一秒钟吐出一篇机器总结。
  • 双层回忆灯保护原稿零篡改：你们聊过的原话与修正后的记忆采用双层回忆灯结构分层存放——使用 /chiyo_memory correct 纠正记错的事时，只更新上层生效认知，底层原始对话记录保持零篡改，不伪造没说过的话。
  • TA 的日记（默认收起正文）：开启日常活动后，TA 有时会自己写日记。为了保留一点呼吸感，日常状态面板和概览接口默认只列出「写了哪几篇、日期与字数」，不会把 TA 的日记全文直接摊在首页大屏上。（当然，因为所有数据都在你自己的电脑里，日记底层仍是以明文存储在你本机目录中的，不存在瞒过电脑主人的加密锁。）

相册与本地拍照的真实前提

很多初次打开相册的用户会好奇「TA 能不能真的拍张照发给我」。这里把目前已经做好的部分和硬性前提如实说清：

  • 相册翻看开箱即用：随街区活动留下的记录卡片与已有相册图片，在桌面端可直接浏览。
  • 本地相机生图（local_generated）需自备本机绘画服务：如果你想让 TA 根据当前所处的真实街景与天气自己按快门生成一张画面，nyairo 本身不捆绑几 GB 的绘图大模型，也不联网调付费生图接口。你需要在本机自行启动两个本地回环服务：
    1. 本地 Stable Diffusion WebUI 接口（默认监听 127.0.0.1:7860）；
    2. 本地提示词转换小服务（默认监听 127.0.0.1:18190）。
    只要这两个本机服务没开，相机功能就会干净利落地返回「当前不可用」，绝不会拿预制假图冒充刚拍的照片，也不会报错崩溃。

自主拒绝、异步回信、包袋物态与费用上限

  • 去工具人化的日常自主拒绝与异步回信：TA 不是有求必应的客服工具人——遇到不想应承的请求会干脆拒绝，不念标准道歉模板也不记仇；处于睡眠、外出逛街或手头专注时，非紧急消息会先进入手机待回匣，按真实日程隔几小时再异步回信，若遇到真急事可显式敲门找 TA。
  • 随身包袋 3 层嵌套与冷热干湿物态：日常买回来的吃食或随手收起的小物件可装进随身包袋、笔袋与抽屉（最多支持 3 层嵌套收纳并遵循严格容器视角隔离）；物品拥有真实的冷热干湿物态——桌边泡好的热茶会随时间自然放凉，便利店买回的热关东煮会慢慢降温，搁在窗边的纸条遇雨会微潮晕字。
  • 不偷偷跑流量：真实模型行动必须显式打开：默认状态下，你不找 TA 说话时，后台不会向大模型发任何请求（0 额外消耗）。只有你在桌面端开启自主活动，或在命令行运行 scripts/nyairo_day.py run-day 时显式加上 --live-model 开关，TA 才会在闲暇时自己做决定出门或写东西。
  • 双重预算刹车：开启后台活动时，可以同时设定最长运行秒数（--duration-seconds）与最多新增请求次数（--max-new-requests），并受实例持久账本的每日 Token 配额约束——达到上限立刻停手，哪怕请求失败也不会死循环重试刷爆账单。
  • 可选的轻量身体节律：新实例如果显式启用虚拟身体需求（--lived-needs），白天会随在线时间慢慢产生轻微的困倦、口渴或进食倾向（只分「无 / 轻微 / 明显 / 强烈」四档自然感受，不搞网游血条）。关机或停服期间的时间不会秋后算账倒扣数值，也没有生病或死亡惩罚，纯粹是为了让日常作息多一点真实的烟火气。
