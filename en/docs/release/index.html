Open-Source License & Site Maintenance

License boundaries between Apache-2.0 and upstream MIT code, release packaging rules, and how this documentation website itself is maintained.

Open-Source License & Third-Party Notices

Original code added in the public nyairo repository—including the memory ledger, virtual world and bodily rhythms, Life Continuity engine, Life Supply draft service, and website documentation—is released under the Apache-2.0 open-source license.

Underlying execution engine (open-source project Hermes, in vendor/hermes): Retains its original MIT license and copyright notices; all other third-party Python and frontend dependencies remain governed by their respective open-source licenses.

Public Repository & Release Policy

  • The public repository at github.com/L1AN929/nyairo contains only source code, neutral starter templates, tests, and documentation—never personal chat databases, private keys, or internal server addresses.
  • Regular installations and upgrades always track pinned GitHub Release tags (currently v0.8.0) and verified checksum archives rather than pulling unfinished development branches.

Licensing Scope Details

Full LICENSE and NOTICE files sit at the repository root. Keep in mind that the open-source license covers the code and documentation only—it does not grant commercial LLM API credits, third-party messaging credentials, or the authors' private persona data.

Release Checklist Order

  1. Run target release tests and sensitive-string scans on a clean staging directory (verifying internal test domains and local user paths are fully scrubbed);
  2. Generate the matching MANIFEST.json, build the release archive and .sha256 checksum file, and verify unpacking and self-check commands under an isolated user account;
  3. Update website install entry points, changelogs, and known-boundary notes in sync, leaving previously published release archives untouched byte for byte.

Maintaining & Updating This Website

This website is a zero-framework static site located under website/ in the repository (built around index.html, style.css, app.js, docs-data.js, and the synced USER_GUIDE.zh-CN.md):

  1. Whenever you edit styles, scripts, or docs data, bump the cache-busting query parameters on style.css?v=..., app.js?v=..., and docs-data.js?v=... in index.html so CDNs and browsers pick up the latest assets immediately;
  2. Before deploying static files, back up the live site to a private path outside the public web root—never leave .bak files inside a publicly served directory;
  3. After deployment, test both desktop and mobile viewport widths in a real browser to verify navigation links, downloads, quick search (Ctrl + K), and code copy buttons all work cleanly.
