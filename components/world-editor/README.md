# nyairo 世界编辑器 · 0.4.0

从空白绘制室内布局、导入家具图片、配置可执行交互，再手动控制居民亲自试一遍。基于完整 v0.3 源码升级，旧版发行目录保持独立。

本程序是 Windows 本地独立版，使用 `nyairo.editor-runtime.v3` 测试后端。无需模型、Key、账号或网络服务；没有接入生产 nyairo、Hermes 或私人角色。居民动作由你手动发出，状态与事件由本机运行时提交。

## Windows 解压启动

1. 将整个 ZIP 解压到可写的普通文件夹，进入 `nyairo-world-editor`。不要只拿出 HTML。
2. 电脑需要 Python 3.10 或更新版本，并加入 PATH。应用本身只用 Python 标准库，不需要安装第三方包、Node 或构建前端。
3. 双击 `start.cmd`，保持命令窗口打开。浏览器出现「午后咖啡馆」即成功。
4. 浏览器地址通常是 `http://127.0.0.1:8766`。在命令窗口按 Ctrl+C 停止服务；关闭浏览器不会停止它。

如果没有自动打开页面，可在解压文件夹的地址栏输入 powershell、回车，执行：

```powershell
python server.py --open
```

端口被占用或 Windows 拒绝绑定时换端口：

```powershell
python server.py --port 8767 --open
```

启动器先检测 `python`，再尝试 `py -3`，不会下载环境。缺少 Python 时安装 Python 3.10+，勾选加入 PATH，重新打开窗口。出现写入失败时检查解压位置是否可写、磁盘空间是否足够。

## 先体验随包咖啡馆

示例是一个区域内的两间室内空间：左侧会客区、右侧水吧。隔墙贯穿区域，门初始关闭，窗不能通行；两边使用不同地面。

1. 点「居民试运行」。居民出生于网格 (5,10)，空杯在 (5,11) 附近。
2. 选择左侧「空杯」，点右侧「拿起」。空杯不能直接喝水。
3. 在下面的目的网格填 X=8、Y=10，点「沿路径行走」。也可点击当前区域空地选目的地。蓝色虚线显示实际搜索出的路径。
4. 点画布隔墙中部的门，在右侧「开门」。再走到 (14,11)，到饮水设备旁。
5. 选择「饮水设备」，点「给持有杯装水」。示例装水耗时 2 分钟，杯子变成装水、份数为 1。
6. 选择仍在左侧列表中的「空杯」，点「喝饮品」。水分增加 20，份数归零、状态为空；再次喝水会失败。
7. 走到门附近可以关门、锁门、解锁；解锁只使门关闭，还要开门才能通过。设备可以切换可用状态；水吧灯可开关；收纳柜保留容量和真实收纳、取出行为。

下方面板显示坐标、持有物、身体、时间和事件。「导出居民存档」保留这些经历；「导出世界包」保存场景与初始规则。

## 从空白亲手搭咖啡馆

所有步骤都在界面完成，无需修改 JSON。

1. 点「新建」并确认。选第一个区域，改名咖啡馆；将区域放在 x=75、y=80，宽=850、高=500，便于创作。选咖啡馆主题或自行改颜色。室内空间默认开启，入口网格默认 (5,10)。
2. 切换「空间」，选「画墙」，从区域上方中线向下拖出竖直隔墙。绘制自动选水平或竖直方向，吸附每格 5%。选墙在右侧改为起点 (50,0)、终点 (50,100)，得到贯穿区域的隔墙；不要留下两端绕行的空隙。
3. 选「放门」，点击隔墙中部。右侧设沿墙起点 45、长度 15、初始状态关闭，保留开门/关门/锁门/解锁用途。选「放窗」可在上方墙段放窗，例如起点 15、长度 15。门窗不能重叠或超出墙长。
4. 选「画地面」，分别拖出左右两个分区。左边设 x=0、y=0、宽=50、高=100，木地板、颜色 #eee7d8；右边设 x=50、y=0、宽=50、高=100，方砖、颜色 #dce7e5。也可在地面属性选择导入图片。
5. 切「物件」，从左侧内置素材选择桌子、椅子、杯子、饮水设备、柜子和灯，再点区域放置；或直接拖入。建议杯子 x=25、y=55；设备 x=75、y=55；其他家具避开门口。物件可通过右侧位置字段精确调整。
6. 选杯子，将初始物件状态设「空杯」，初始份数会同步归零。保留拿起/放下/喝饮品用途、水分增加 20，开启接近条件，距离 2 格。
7. 选设备，初始状态「可用」，开启装水和切换可用状态。行为卡片明确显示空杯要求、状态结果；设置装水分钟和装入份数，例如 3 分钟、1 份。接近条件以可达路径计算，墙后的直线近距离不能使用设备。
8. 切「素材」。选择对应类型「桌子 / 柜台」、分类家具、集合「咖啡馆家具」，导入你自己的 PNG / WebP / 静态 SVG。可以先用 `examples/resources/cafe-counter.svg`。右侧改名字、默认大小、朝向、层级和是否交互；图像预览应正常出现。
9. 点击图片素材，再点区域放置柜台；也能从素材库拖到画布。同一张图可以反复放置，实例共用资源，各自保留位置与运行状态。搜索框按名称查找；分类和集合用于筛选。
10. 点「作品与场景设置」填写作品信息，版本使用三段数字，例如 0.4.0。保存草稿、检查世界，然后新建试运行，按照上一节拿杯、开门、走到设备、装水、喝水。
11. 关闭门后跨墙行走应失败；无杯装水、空杯喝水、设备不可用装水都应给出原因，失败不增加时间或扣份数。
12. 导出世界包，在第二个干净实例导入、保存、新建试运行。图片、墙门和参数随包迁移，不依赖原电脑路径。

「区域连接」仍用物件工具中的连接功能，表达两个独立地点的旅行；新增「空间」描述同一个区域内部的墙、门和可行走房间，二者可以同时使用。区域旅行要求目标连接且开放；启用空间后，还须能到达本区域入口，避免绕过关闭的隔墙门。

## 空间与规则操作

- 选择 / 移动：拖动墙、地面、门窗；墙端点、门窗长度在右侧修改，坐标/长度须为 5 的倍数。方向键每次微调一格。
- 复制墙包含依附的门窗，副本使用新 ID。删除墙会一并删除依附门窗，确认框明确显示影响；一次撤销可完整找回。
- 地面、墙/门窗、家具辅助层可分别隐藏；隐藏仅影响创作视图。预览和试运行仍显示实际结构、执行真实通行规则。
- 规则页与物件属性使用同一组后端模板。当前唯一执行者是独立测试居民；勾选用途决定它能执行的动作。有限模板的物件要求和状态条件是固定语义，时长、份数、水分、接近开关与距离可配置。
- 保存初始定义与当前运行状态分开。修改空间、图片或规则后，旧试运行继续使用冻结内容；要体验修改，点「从草稿新建试运行」。创作撤销不会倒退居民经历。

## 编辑操作

| 操作 | 使用方式 |
| --- | --- |
| 视图 | 缩放按钮 / Ctrl+滚轮；「全图」恢复视图；平移工具或空格拖动画布 |
| 拖动 | 勾选「拖拽」，移动区域或物件；Esc 取消；物件可跨区域移动，区域外落点取消整次移动 |
| 网格 | 显示与吸附分别控制；吸附以 25 个地图单位为步长，物件仍存为区域内整数百分比 |
| 多选 | Shift 点击；框选工具可选择区域或物件，以中心点是否在框内判断 |
| 批量移动 | 拖动任一选中对象，整组移动；选中区域及其内部物件时，内容只移动一次 |
| 复制 | 按钮或 Ctrl+C / Ctrl+V / Ctrl+D；跨区域粘贴可先选择目标区域；区域复制包含内部物件与组内连接 |
| 对齐 | 选择同类对象，选择方向后「整理」；物件需在同一区域；等间距至少三个 |
| 属性批量修改 | 多选物件可统一尺寸，多选区域可统一主题；一次批量操作为一步撤销 |
| 右键 | 复制、创建副本、连接、顶层/底层、删除；删除提示实际影响 |
| 键盘微调 | 画布对象获得焦点后用方向键；Shift 加大步长；尺寸控制点方向键调整大小 |
| 历史 | Ctrl+Z、Ctrl+Shift+Z / Ctrl+Y；输入框内保留文字撤销；Mac 使用 Command |

选择物件后可调整 40–200% 的视觉尺寸、0–359° 朝向、排列层级和名称显示。视觉尺寸不改变家具占用或移动规则。层级只控制物件之间的绘制顺序，不做跨房间的深度遮挡。

撤销只作用于创作：属性、拖动、批量布局、复制、删除、连接和导入。最多 40 步，并受约 32 MB 快照预算限制；刷新后历史重新开始。视图缩放和平移不造成草稿脏状态，也不影响居民经历。

「列表」「属性」可折叠两侧面板；「场景预览」隐藏网格、连接、选择框和控制点，不丢失未保存修改。手机界面支持操作和滚动，但密集布局创作更适合电脑。

## 保存、恢复、冲突和备份

正式草稿需点击「保存草稿」。修改后约 250 毫秒写浏览器副本，并写入当前数据目录的 SQLite 恢复副本；「本机恢复副本已更新」表示本地服务已确认写入。未完成的字段可保留在恢复副本中，正式保存仍需通过完整校验。

关闭整个浏览器、重启服务后，使用同一数据目录，恢复提示仍可找回服务已确认的副本。换端口或换浏览器也可从本地服务发现副本。每个页面有独立 ID 和递增序号，旧的延迟写入不能复活已清除的当前副本。浏览器副本同时按地址和实例标识隔离。

「暂不恢复」只隐藏提示。恢复另一副本或新建世界时，当前未保存内容会另存一份；旧副本可能继续出现在恢复列表中。关闭页面前尚未完成确认的最后修改不能保证保留，请等待确认或手动保存。存储失败会显示提示，不会假报正式保存成功。

另一窗口保存新版后，旧窗口保存返回冲突；旧恢复副本也不能覆盖新版。先导出要保留的修改，再「回到已保存的草稿」。本版不自动合并冲突。

所有正式草稿、试运行、动作回执及服务恢复副本存放在 `data/editor.sqlite3`。整体备份：先停止服务，再复制整个 `data` 文件夹，包括 SQLite 辅助文件。恢复时停止服务，换回完整备份，再启动。副本不代替整体备份。

## 世界包、存档与升级

应用 v0.4 对应世界包 v3、运行时 v3、居民存档 v3；这些是独立编辑器接口，不是生产 nyairo 版本。

世界 JSON 包含场景、区域连接、室内结构、物件规则以及实际被物件/地面引用的图片资源。未使用的素材留在本地草稿库，导出世界时会剔除。图片以受控 MIME 与 Base64 内嵌，因此只复制 JSON 即可跨实例使用。导出同时在数据目录 `exports/` 留下真实世界文件和 SVG 封面；提示会显示路径，浏览器阻止下载时从该目录取文件。

居民存档包含冻结世界、实际坐标、路径、门状态、物件状态/份数、持有与收纳、身体、时间和最近 200 条事件。恢复会创建新的试运行，不覆盖原居民或编辑草稿。不要用世界包替换居民存档。

可读取真实的 v0.2 世界/存档 v1 和 v0.3 世界/存档 v2。旧世界补入关闭的空室内结构、空素材库和不要求接近的默认条件，保留原有行为效果。旧存档先验证原内容摘要，再升级；不会将已经读过的书、消耗的饮品或身体与时间重置。v3 导出无法在 v0.3/v0.2 中使用，旧编辑器会提示不兼容；本版不提供降级导出。

升级数据时先停旧服务、备份完整 data，再启动新程序指向原数据目录。旧草稿版本加一次防止旧窗口覆盖；试运行 ID、经历和动作回执保留，补入新状态字段。升级后回退旧版须恢复升级前完整备份，不能让两个不同版本同时写同一个数据库。

第二实例使用不同端口、独立目录：

```powershell
python server.py --port 8767 --data-dir .\second-data --open
```

限制和详细字段见 [FORMAT.md](FORMAT.md)、[KNOWN_ISSUES.md](KNOWN_ISSUES.md)。验收报告见 [TEST_REPORT.md](TEST_REPORT.md)，施工前代码核查见 [IMPLEMENTATION.md](IMPLEMENTATION.md)。

## 源码与开发验证

```powershell
python -m unittest discover -s tests -v
node --test tests/test_editor_state.mjs tests/test_layout.mjs tests/test_space.mjs
node --check web/app.js
node --check web/editor-state.mjs
node --check web/layout.mjs
node --check web/space.mjs
```

Node 20+ 只用于开发测试。应用没有 Node 运行依赖。

`legacy.py` 保留 v0.3 的校验和原行为语义；`model.py` 扩展 v3 格式与状态/动作；`space.py` 负责室内几何及网格路径；`resources.py` 负责静态图片；`store.py` 继续管理原 SQLite 事务、保存和回执；`server.py` 只监听本机；`web/` 无构建步骤。示例、自动化测试及实际界面截图随包提供。
