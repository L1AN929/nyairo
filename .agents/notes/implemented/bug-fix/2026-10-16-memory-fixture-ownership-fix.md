# Agent Note: 记忆系统所有权解耦与检查夹具归属定位

Status: implemented

## Problem

在早期的持续集成与健康检查中，Memory 模块的 3 项基线检查频繁出现失败。初步排查容易被误认为是 M0 长期记忆存储引擎本身损坏或存在致命 Bug，导致多次尝试重写或更换底层数据库实现，险些造成记忆协议的破坏性倒退。

## Decision

NyAiro 确立所有权与检查主体绝对解耦原则：
1. 定位真相源：排查证明 M0 记忆底座完全正常，失败的真正原因在于检查夹具中的查询主体（workspace subject）与内部真实人格所有者（persona owner）存在所有权不匹配。
2. 保护底层产品缝合线：严禁在未弄清根因的情况下私自篡改 M0 核心记忆契约或引入未经授权的第二套外部记忆引擎。
3. 负控验证：通过修复测试夹具的所有权声明，并补充旧逻辑的反向负控用例，确保证据的真实与可重现。

## Alternatives considered

- **推倒重来更换第三方向量/图数据库** — 看似能直接跳过报错；但会彻底摧毁既有的轻量化本地 SQLite 记忆索引，引入大量重度外部服务依赖，得不偿失。
- **直接关闭或跳过这 3 项失败测试** — 迅速让 CI 变绿；但这掩盖了所有权传递的真实隐患，会导致生产运行时记忆查询始终命中空集合。

## Consequences

- **收益**：保护了稳定的 M0 记忆底层契约，避免了无意义的架构动荡，将记忆模块的测试通过率提升至确定性合格。
- **代价与已知上限**：后续所有跨模块接入记忆系统的调用者，都必须严格遵守 persona owner 的契约传参，不允许模糊代称。
