# v0.2.1 三项旧账修复（FIX-1/2/3）

**Problem**：三条评审遗留问题在当前树上仍在。FIX-1：`IntegrationStore` 的落盘把 `os.fsync` 门控写成
`if fault_hook is not None`，只有测试注入故障钩子才同步，生产反而走延迟快照——持久性做反了。FIX-2：
resident 启动只调 `runner.reconcile_pending()`（仅收口 AR-0 UNKNOWN），LR-3/LR-4/AG-2/AR-1 的冷恢复
`recover_all_and_reconcile` 无人调用，上一个进程半途留下的记录永远不闭合。FIX-3：summary 的
`cognition_attached` 读的是 `cycle.runtime`（恒存在），恒为 True，接没接真实认知适配器看不出来。

**Decision**：按施工单做最小修复，参照 `v021-fixes-reference.patch` 的逻辑、按现树位置重写。
FIX-1 改成 `do_fsync = fault_hook is not None or self.namespace != NAMESPACE_ISOLATED_TEST`，
与 `activity_continuity` 既有规则同款；三处 `if fault_hook is not None`（WAL、journal、快照）统一用它。
FIX-2 在装配完成、`reconcile_pending` 之前调用 `runtime.coordinator.recover_all_and_reconcile()`，
结果存 `self.cold_recovery` 并写进 summary；失败记 `last_error`，不阻塞启动；0 模型调用。
FIX-3 在 `start()` 里记 `self.cognition_is_real = cognition is not None`，summary 读它。

**Alternatives considered**：直接把参考补丁打上去——补丁基于 35df37f，行号已漂到 2520/2533 一带，
且含 FIX-4~6，本轮只要三项，整包合会顺带改计费与预算接线，故否决。FIX-2 另考虑在 runner 里做，
但那会把冷恢复塞进只管 AR-0 的层，扩了它的职责，否决。FIX-3 另考虑从 cycle 取适配器再判空，
仍绕一层间接，且要求 cycle 暴露内部对象，否决。

**Consequences**：生产路径现在真的 fsync，写盘变慢但崩溃后可恢复；隔离命名空间行为一字未变
（`fault_hook` 为空时 `do_fsync` 仍为 False）。冷恢复每次启动多一次全店扫描，0 模型调用，换来
半途记录能被闭合。`cognition_attached` 从此能如实为 False。**未改**其他调用点、未扩功能、未动
FIX-4~6。验收：check_life 及 b7/b8/b8-6a/b8-causal/memory-v02 六套全绿；v02 隔离验收在
[7]CONFLICT/[8]UNKNOWN 两节红，已用未改动 HEAD 跑同一套对比，红点与报错完全一致，属既有问题
（新加的 reconsideration 门在同一 (target, revision) 上拒第二次花费），不是本次修复引入。
