# Agent Note: 瞬间感受只当临时参考：绝不当成固定情绪、事实或行动指令

Status: implemented

## Problem

之前子智能体写了个记录即时反应的模块 `short_appraisal_view.py`（比如喝水烫到了喊一声、走路久了叹一句），写完后发现全系统根本没有其他代码去读取它，成了代码库里的摆设。但如果随随便便把它接进生命循环，会引发两个灾难性的 Bug：一是 AI 会凭一句话的语气瞎猜自己的情绪（比如叫了一声疼，就脑补自己陷入抑郁）；二是系统容易把一秒钟的吐槽当成不可篡改的长期事实存盘，甚至直接把它当成最高优先级的行动指令（Candidate），逼着虚拟人强行去做多余的动作（比如立刻跑去吃药看病）。

## Decision

生命主循环 `AutonomousLifeCycle` 把这套短期感受严格接成“当前轮次的只读临时参考”：
1. 只读透传不加戏：`cycle.read_appraisal()` 只负责转发有效视角的感知内容，中途绝不加工，读取失败就老实记录 `read_error`，绝不靠脑补猜数据。
2. 标志位严格防伪：塞给模型的每一条即时评价，必须在字典里明文写死 `authority: None`、`candidate: false`、`stable_fact: false`、`tone_inference_used: false`，从物理上剥夺它冒充权威、冒充事实、或者凭空生成行动指令的资格。
3. 塞入临时上下文通道：有效评价只与当轮已准入的经历一起装进 `prior_experiences`（`consideration_context()`）供模型做眼前决策参考，绝不为此新建落盘文件，也严禁调用接口往长期记忆 Memory 库里写。
4. 过期立刻蒸发：只要评价失效、时效过期或者被后续事实纠正，当前轮次立刻清空丢弃；空评价绝不会触发多余的模型推理，绝不浪费算力。

## Alternatives considered

- **给决策请求 `CognitiveDecisionRequest` 专门加个新字段** — 结构看起来最干净；但这属于侵入核心协议的越权破坏，用现有的 `prior_experiences` 容器配合 `kind` 字段分流就能完美解决，没必要大动干戈扩改契约。
- **把感受硬塞进身体容量 `capacity_summary` 里** — 字段看起来现成好用；但这等于把瞬间的主观嘀咕伪装成了身体客观数值，是把主观投影冒充身体事实的恶劣做法。
- **给评价新建一个本地落盘存储（Store）** — 能把一时的感受永久存下来；但系统里根本没有合法的情绪权威为它背书，凭空落盘只会制造出互相冲突的假历史。
- **让感受直接生成行动指令（变成 Candidate 甚至 PERSONAL_OPPORTUNITY）** — 能瞬间让 AI 动起来；但那是把一时的嘀咕当成了圣旨，直接违背了必须由合法世界事实和 AG 决策链驱动行动的底线。

## Consequences

- **收益**：`short_appraisal_view.py` 从无用的代码摆设变成了真正能辅助即时决策的有效输入，既让智能体当下做决定更有生活温度，又彻底焊死了情绪发疯、虚假事实和越权发指令的风险。
- **代价与已知上限**：读取端需要按 `kind` 字段把评价和正式经历分开处理；在没有正式接入真实情绪所有者（S07 owner）之前，这套机制在生产中保持为空，绝不能对外吹嘘系统已经拥有了长期稳定的心理情绪。
