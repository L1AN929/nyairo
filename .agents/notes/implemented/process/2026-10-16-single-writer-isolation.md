# Agent Note: 多个 AI 干活必须独占写代码：监工只准挑刺，不准两人同时改核心

Status: implemented

## Problem

在给 NyAiro 施工时，同时开了多个智能体（比如监工 GPT 和干活的 DeepSeek，或者同时跑两个修复子智能体）。如果让两个 AI 同时去改同一份核心调度代码，它们不仅会互相覆写对方刚修好的文件、把测试夹具冲乱，还会产生你改你的、我改我的混乱脏树，最后单元测试挂了一大片，根本查不出到底是谁改崩的。

## Decision

立下一刀切的写权限铁律：
1. 一批任务只有一个 AI 能碰核心代码：比如 D 阶段只允许唯一的修复子代理去改核心，其余所有代理绝对禁止写入核心文件。
2. 监工只能看不能摸：总监工 GPT 只负责审查代码、跑测试命令、提修改意见和改管理文档，严禁亲自下场改动核心业务代码。
3. 严格按 Git 状态验收：代码测完必须精准归属，不准把满地的未跟踪垃圾文件一股脑打个脏包糊弄通过。

## Alternatives considered

- **让多个 AI 完全自由并行写** — 看着并发很高很爽；但实际上一跑测试全是冲突报错，两个人互相踩脚，两分钟就能把代码库搞烂。
- **完全变成单线程，所有任务一个个串行排队** — 绝对不会冲突；但连梳理只读文档、跑独立测试这种无关紧要的活也要死等，效率太慢。

## Consequences

- **收益**：彻底消除了代码被别的 AI 悄悄覆盖的惨剧，代码出了 bug 一秒就能定位到责任人。
- **代价与已知上限**：每次派新任务给子代理之前，主代理必须先想清楚它要动哪些文件，稍微多了几秒钟的派工规划。
