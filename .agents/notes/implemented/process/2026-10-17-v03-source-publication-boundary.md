# Agent Note: v0.3源码推送与官网发布保留旧发行包

Status: implemented


Superseded-by: [v0.3.0 发行版本指针更新](2026-10-19-v03-release-install-pointer.md)（只取代“无 v0.3 安装包、安装入口保持 rc3”这一条；发布白名单与单写者隔离继续适用）
## Problem

用户在本地v0.3限定验收后授权推送GitHub并更新nyairo.com。原工作树保存大量已验收但未提交的产品、测试和文档，origin指向本地审阅副本；GitHub main还有五条文案更新。直接整仓add、强推或把官网安装链接改成未制作的v0.3 ZIP，会混淆提交对象或损坏有效安装入口。

## Decision

发布使用明确文件白名单和独立临时Git索引，以最新GitHub main为父树，叠加本版已验收增量与官网内容。原工作树、原分支、原origin和真实索引保持不动；推送main仅允许正常fast-forward，远端若又变先重新核对，不强推。提交使用仓库既有公开署名的命令级身份，不修改全局配置或凭据。

官网只更新已授权nyairo.com的公开静态内容，源站是香港`/var/www/nyairo`，不是另一个会话维护的项目看板。上线前在公开目录之外保留目标文件与哈希，检查目标未被并行覆盖，白名单上传后以源站Host头与公网实际内容验证。没有nginx、Cloudflare、后端或生产profile改动。

本次是源码与验收说明更新，不创建v0.3安装包或自动迁移实例。旧v0.2.0-rc3标签和下载地址保留；官网、README与测试页明确区分源码版本和可下载安装版本。公开文档只将本机用户名路径替换为通用占位符，实测数字、失败记录和权限边界不改。

### 既有决定检索

- [版本停止线](2026-10-19-v03-bounded-feature-freeze.md)：部分重叠；功能停止保持，用户新授权仅增加源码提交和官网部署，不重新打开产品施工。
- [单写者隔离](2026-10-16-single-writer-isolation.md)：继续适用；官网内容、公开文档路径脱敏、父级发布写集分离，后端产品零修改。

## Alternatives considered

- **直接add整个dirty树再强推main**：最快，但会漏审无关内容、丢掉远端新文案；拒绝，使用审定白名单和远端父树。
- **新clone整仓再重跑全套**：结构直观，但复制巨大vendor/重刷不变测试无必要；独立索引提供树级隔离，冻结成员逐字节核验与已有最终矩阵可复用。
- **把所有官网安装链接改成v0.3**：版本展示统一，但没有安装ZIP/新manifest/迁移验收，链接会失效或误导；保留rc3安装入口，公开源码更新状态。

## Consequences

- 收益：远端既有更新被保留，本版源码公开而不改生产运行状态；官网更新有备份与内容证明。
- 代价：本地工作树仍是旧分支的未提交候选，不因为远端提交成功就变clean；v0.3不是可直接通过现有更新器安装的发行包。
- 最终发布结果另记公开回执；本笔记规定已采用的发布边界，不提前宣称推送或上线成功。
