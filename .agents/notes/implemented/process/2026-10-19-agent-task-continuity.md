# Agent Note: 长任务用有界落盘检查点恢复，不靠无限对话摘要

Status: implemented

## Problem

长期施工反复压缩会丢失真正停点、已消耗授权和writer归属，导致重读设计、重跑绿测试或误把旧失败当待执行计划。继续扩大摘要本身又挤占上下文。用户明确要求解决此问题，而不是另加产品能力。

## Decision

项目AGENTS指定 `.agents/continuity/current.json` 为唯一当前任务检查点，协议在相邻README，`scripts/task_resume.py` 为只读恢复入口。它是agent管理工具，不进入NyAiro生活/Memory/runtime，不改变PI-Desktop压缩设置。

检查点上限8000字符、1–3个下一步、1–5个局部文件anchor，保留目标、阶段、精确停点、禁止重复、边界、writer/write-set、历史预算与进程、证据入口。阶段历史放已有父级报告，技术理由仍归notes；不再把全部旧摘要复制回来。

更新发生在用户改方向、长命令/派工前、关键结果后及阶段结束前；revision递增、真实时间、父级单写。恢复入口只读Git身份、局部anchor和证据是否存在；缺失/损坏/身份或anchor冲突返回STOP/2，具名核对，不修文件、不reset。证据不可访问只warning，不把存在路径当正文证明。正常READY/0只代表可接续，不是产品健康或行动授权。不会执行检查点里的命令。

长期记忆只放稳定入口，不复制易过期账本/PID。操作前仍查当前writer/lease/预算；旧时间窗口不能因压缩刷新。检查点坏了从最近父级报告和具名事实恢复，不猜测。

检索重叠：既有[单写者隔离](2026-10-16-single-writer-isolation.md)部分重叠，沿用不替代；架构中的Activity continuity是产品行为，与agent上下文恢复无关。本次不归档/删旧文档。

## Alternatives considered

- **继续扩大压缩摘要。** 最强理由是零工具改动、信息似乎最全；否决：旧日志占满上下文，当前状态与历史混在一起，没有单一停点，也没有防重复消耗边界。
- **只存长期记忆。** 最强理由是新会话可检索；否决：动态任务进度容易过期并形成多份真相，故只保存项目入口。
- **改宿主插件自动拦截压缩。** 最强理由是可在中断前自动保存；本次不采用：需改变宿主配置/加载流程、扩张scope，当前用里程碑前写入降低突然中断损失，不宣称能拦截所有压缩。

## Consequences

恢复只读取短检查点和一份当前报告，避免整个项目历史回放；相同HEAD下仍以少数本步anchor识别关键dirty变化。不做全树SHA/测试巡检。代价是父级必须持续更新，未到保存点的突然中断仍可能丢少量未记录推理，旧scratch也可能消失；协议如实暴露这些上限。新用户要求优先，检查点不越过权限规则。

## Verification

`tests/test_task_resume.py`覆盖新读者恢复、spent budget保留、anchor/branch冲突、证据缺失、坏/缺检查点、超长、路径越界及只读CLI/退出码。测试夹具放session scratch且保留；仅测试管理工具，不跑产品或真实模型。实际从仓库外执行恢复命令核对当前目标、停点和剩余真实运行授权为0；具体结果留在session scratch continuity-check报告。
