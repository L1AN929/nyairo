# Agent Note: v0.3按用户停止线收束为后端连续生活版

Status: implemented

## Problem

总体设计包含193个规划能力，持续按ZIP施工没有自然结束点。用户现在明确要求达到可命名为0.3的大版本就停止加功能，随后测试并对比GitHub的0.2。已有较大未提交产品增量和两路在途收尾，若继续派Future/Agenda生活接线，会不断移动验收目标。

## Decision

本轮以v0.3“后端连续生活版”为有界候选：纳入既有导航/持久行程、安全暂停和UNKNOWN恢复、请求预算、私人事项与连续性、有限街区消费/停留及最后在途的World只读营业预期。所有产品作者结束后冻结，不再派未启动的Future/Agenda Life接线、UI或其他规划功能。最终测试只允许针对本版具体故障的窄修，不追加能力门槛。

对比以GitHub公开v0.2.0-rc3发布commit为准，区分rc3到后续main的已提交增量和当前未提交增量；早期v02-baseline施工文档不是rc3最终能力证据。测试覆盖本次变更的代表行为、重要负控/恢复和一次同实例连续链，已接受的不变owner宽回归不重复。失败日志和夹具保留，真实子进程返回码作为结论依据。

本地候选仍UNCOMMITTED；版本定位不创建git标签或远端发布。测试完成与更新说明交付后停止功能工作，真实模型/24h/部署/提交等仍需另行授权。

## Alternatives considered

- **继续完成整个ZIP再命名0.3**：覆盖面更完整，但193能力与后续依赖不是本版闭合条件，违背用户要求的停止线，验收永远追着变化。
- **立即中断在途写入并冻结半成品**：最快停止，但营业预期和丢回执验证已进入收尾，强停会留不明状态。选择收口已启动包，不开启新Life整合。
- **重跑所有仓库测试作为大版本证明**：可发现更广回归，但包含不变owner和破坏性旧清理，不符合既定适度验收；采用与变更匹配的系统矩阵，公开未测范围。

## Consequences

- 收益：v0.3有明确产品主题、停止条件、对比基线与可审计测试对象，不以ZIP覆盖数或用例条数代替完成度。
- 代价：UI、Future/Agenda接线、承诺协商、真实模型一天等仍未交付，必须在更新说明显式列出；本地未提交候选不是可下载的正式GitHub release。
- 最终验收前本笔记只证明流程已收束，不证明所有测试已通过。产品后续窄修会记录原因并重新验证实际影响范围。
