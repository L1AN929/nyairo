# Agent Note: 派工失败的分类处理纪律（按退出形态走，不把警告当根因）

Status: implemented

## Problem

派工链分两层：启动前的 probe 检查模型链，worker 进程内有整单 deadline。一次 3600 秒工单
最终零产物，stderr 带有 `claude-code:unrecognized_model` 警告；事后翻日志，无法判断它卡在
等 API、静默长命令还是某个工具，因为现有采集只在 attempt 结束后才把 stdout/stderr 写盘，
没有逐请求时间、首字节、心跳或 session 关联。

没有统一口径时，几种错误处理反复出现：把警告直接当根因换模型；把 exit3 当成“已经跑了一小时”；
把整单 exit124 当成果全败而整单重做；或者反复加 timeout 把问题压下去。本 note 记录的是已经
采用的**处理纪律**，不是派工链已修好，也不声称那次卡点已经定位。

## Decision

按失败形态分类处理：

1. **exit3（probe 未通过）**：worker 尚未启动，日志文件也还没打开。先看外层具体错误；
   暂态连接超时在有效授权下最多一次同入口重试；400/401/403/404 先核参数、权限、端点与模型名，
   不盲试、不靠换模型绕过。
2. **exit124（整单 deadline）**：先确认原 writer 及子进程已停，再验盘上产物；有绿收绿、
   只返修缺口；未知副作用不重放；连续零产出即停。**不把加 timeout 当根治**。
3. **exit1 且轮数耗尽、无 TIMEOUT**：单独一类。收落盘成果，按具名缺口有限补交，
   不当作网络或派工可用性故障。
4. **警告与进展并存**：`unrecognized_model` 在本机 2.1.265 客户端二进制里是 warn/telemetry
   路径，且 5 份 exit0 成功工单带同一警告。因此“有警告 + 有可核进展/有效交付”不换模型、
   不按故障重跑；只有出现明确 HTTP 拒绝时，才按状态码与路由证据单独处理。
5. **换通道或模型**：必须明确批准并核对兼容性，不能借诊断顺手改配置。
6. **数值边界**：probe 默认的 8 秒是单次 socket 操作 timeout，不是整次 probe 的严格总上限；
   worker 层另有整单 deadline。两者不能混算，也不能用 exit3 推断“等了一小时”。

可观测性现状：本次只确认了 122201 这一单 3600 秒零产物；更深的卡点仍是 UNKNOWN。
若要定位，需要脱敏的实时阶段/时间戳、session 关联和已有 debug 状态的采集，这属于新的
待批准选项，本 note 没有改脚本、没有开 debug、没有采集 prompt 正文或密钥。

## Alternatives considered

- **直接忽略所有警告。** 最强理由：同警告出现在 5 份成功日志里，说明它不阻断派工，忽略它
  能减少噪声；否决：忽略会把真正的 HTTP 拒绝一起吞掉。本次警告与零产物同时出现，虽不能
  证明因果，也不能证明无关，只能说“不必然致命”。
- **一遇到问题就自动切换模型或通道。** 最强理由：切换可能一步绕过卡点，恢复最快；否决：
  “换模型就好”从未被验证过，切换会改变施工模型、配置与可复现性，也可能绕过权限边界。
  必须明确批准，不能由诊断自行升级。
- **一律加时限。** 最强理由：成本最低，不必区分失败形态；否决：现有日志无法判断是否时限不足，
  单纯加时不能定位根因且可能扩大无进展等待，而且掩盖“没有可观测性”的真实缺口。
- **整单重做。** 最强理由：简单，不必判断哪些产物有效；否决：未知副作用不能重放，已落盘的
  有效部分应保留、只返修缺口；整单重做还会重复消耗额度。
- **把 probe 的 8 秒当成整单硬上限。** 否决：它只是单次 socket 操作超时，覆盖不了 worker
  层的整单 deadline，混用会误判“已经等了一小时”。

## Consequences

好处是失败分类明确：重试有界、不把警告当根因、不把 exit3 当已运行、不把 exit124 当全败。
代价是现有日志仍无法定位卡点，最坏情况下还会再耗一整轮时间；真正的定位需要等可观测性方案
获得批准后再做。规则不改变按单时限本身——3600/5400 秒与 300 轮仍按
[按单时限](2026-10-24-per-task-worker-timeout.md)执行，本篇只管失败之后怎么处理；
写集独占仍按[单写者隔离](2026-10-16-single-writer-isolation.md)，失败重试也不开第二个 writer。
