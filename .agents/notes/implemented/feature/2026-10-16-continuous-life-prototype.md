# Agent Note: 生活雏形以同一实例连续日常链作为集成验收标准

Status: implemented

## Problem

传统的单元测试通过或接口对齐往往只能证明孤立模块的技术可用性，无法保证智能体在真实时间流动中能够顺畅生活。这容易产生“单测全绿，但多轮行动串联时智能体状态断裂或调度卡死”的假象。

## Decision

NyAiro 确立生活雏形大阶段集成标准：
1. 连续日常验收：阶段性验收必须以“一个入口、同一实例、一段连续日常”为测试单位。
2. 真实场景闭环：将地点移动、路程消耗、环境条件、身体后果与心智经历完整串联，拒绝单点孤立断言。
3. 状态恢复刚性：同进程或跨生命周期的状态重建必须有真实状态持久化与恢复证据，杜绝虚假标记；"重启"的当前证据是两个独立进程各自装配真实 runtime 并续上同一 Activity（见 [跨进程重启 harness](../testing/2026-10-17-cross-process-life-restart-harness.md)），只读读盘 probe 与同进程重建都不算。

## Alternatives considered

- **仅以单元测试全绿作为阶段通过标准** — 最容易跑通流程；但完全无法暴露多动作交替时的状态阻塞、锁竞争以及记忆恢复断裂问题。
- **直接上线 24 小时真实生产无休运行** — 最贴近终极目标；但当前阶段模型算力消耗不可控，底层调度成熟度未闭环前极易死循环烧额度。

## Consequences

- **收益**：确保每一个交付的大阶段都具备真实可连续体验的生活质感，而不是零散模块的代码拼盘。
- **代价与已知上限**：单次集成演练与场景回归耗时较长，对前台状态与后台调度的协同精度要求极高。
