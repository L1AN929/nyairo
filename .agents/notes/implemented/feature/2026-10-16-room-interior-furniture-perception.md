# Agent Note: 房间家具必须有真实坐标与碰撞体：拒绝虚无缥缈的文字纯脑补

Status: implemented

## Problem

房间一度只是提示词里的一段文字：「卧室里有一张床、一张书桌，桌上有个苹果」。模型想躺下就直接宣布躺下，想吃苹果就直接宣布吃到了苹果——不管自己人在厨房还是刚进门，也不管桌上到底还有没有那个苹果。这种纯叙事的世界有三个硬伤：第一，位置无意义，一次都没走过路也能拿到隔壁房间的东西，于是「出门」这个动作没有任何代价，生活变成瞬移；第二，物件状态无人负责，同一个苹果可以被吃到三次，两个人（或两条实例）同时拿着同一把椅子；第三，无法验证，日志里全是模型自己说发生的事，没有任何可核对的事实，出了问题只能靠猜。

## Decision

房间与家具必须有真实几何、真实坐标和真实的交互距离限制，物件的权威状态由世界结算层说了算：

1. **每个房间有坐标与连通关系**：房间不只是一段描述，而是一个带尺寸、带门、带邻接表的结构；移动要结算耗时与路径，跨房间拿东西必须先走过去。
2. **每件家具与物件有坐标与碰撞体**：桌、床、椅、柜都有自己的占位矩形，不能穿过、不能重叠摆放；物件的坐标挂在所在的家具或房间格位上，谁拿了谁没拿由世界记账。
3. **交互有距离门槛**：拿东西要真的走近到交互半径内，躺下要在床的占位范围内，坐着要贴着椅子。距离不达标，动作直接拒绝并回报原因，而不是让模型「再想想」。
4. **感知只给真实处境**：模型看到的是「你在卧室，距离书桌 1.2 米，桌上有苹果」这种可核对的事实，而不是可以随意脑补的叙述文本。世界不允许用一句 prompt 凭空生成不存在的物件。

## Alternatives considered

- **全局物品随时瞬间移动，谁想要就出现在谁手边** — 演示效果最丝滑，零实现成本；但位置彻底失去意义，移动、路程、时间全部报废，生活感归零。
- **纯 prompt 叙事，不做任何物理支撑** — 最省事，全靠模型文笔；但世界不可验证、状态不可对账，模型自己跟自己矛盾时没有任何权威可依，也无法与动作台账对账。
- **只做粗粒度的房间级位置，不做家具级坐标** — 实现量减半；但拿东西永远只能靠嘴上说「我拿了」，无法约束「走近了才能拿」，也挡不住同时持有两件占位物件的荒谬状态。

## Consequences

- **收益**：所有位置、持有物、交互都变成可核对的事实，动作能不能做成由距离与几何决定，不再由模型口才决定（动作的完成确认见 [动作执行必须走三段式真实结算](../architecture/2026-10-16-action-reality-ledger-settlement.md)）。
- **收益**：为后续街区出行与路径耗时打好了底板，房间只是这套几何体系的一个小尺度特例。
- **代价与已知上限**：每个房间都要手工摆坐标与碰撞体，新增家具比写一句话麻烦十倍；感知帧的数据量随物件数增长，需要控制每帧投递的可见范围。
