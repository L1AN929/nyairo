# Agent长任务续接（不是产品Memory）

## 恢复入口

在任何目录可运行：

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
py -3.13 -X utf8 D:\nyairo-rc1-body-backend\scripts\task_resume.py
```

返回0=仓库身份/少量承重文件与检查点一致，可按下一步接续；不是产品健康PASS。
返回2=检查点缺失/损坏或指定文件变化，只核对具名差异，禁止reset、覆盖或全库复验。
证据文件消失只给warning；没有正文就不能继续引用其结论为已验证。工具从不启动服务、联网、花模型预算或执行检查点内命令。

## 分层，不复制长历史

- `current.json`：唯一当前检查点，硬上限8000字符，建议4000–6000。记录目标、阶段、精确停点、最多3个下一步、不能重复、边界、writer、历史进程/预算、证据入口、最多5个本步承重文件hash。
- `docs/engineering/*-parent-result.md`：已完成阶段的结论和证据，按需读取；不要复制回检查点。
- `.agents/notes/`：不变量和为什么这样做，不当工作日志。
- session scratch：原始输出/临时测试；可能随会话删除，关键结论必须留项目报告，不把失效路径当证据。
- 长期记忆：只存稳定入口/规则，不再复制当前账本、PID、任务进度。

## 什么时候保存

1. 用户改目标/边界时，先改检查点再做新方向。
2. 长命令、真实动作或派工前：保存write-set、delegate id、基线和**共同**预算上限；不能等压缩通知才写。
3. 关键结果回来：落原始输出，更新成功/失败/未知、退出码、消耗与下一步，再继续。
4. 阶段完成或主动切换上下文前：写真实停点、未闭合操作、writer/服务最后状态。

用Edit更新，revision递增、updated_at用真实当前时间；单一父级writer。工具报告anchors变化时，先读差异，确认归属后再更新hash，不能只改hash消警。检查点半写/JSON坏就STOP，读旧阶段报告恢复，禁止猜测。

## 压缩/新会话后的顺序

读AGENTS→运行恢复命令→读一份当前阶段父级报告→仅核对下一步涉及的实时事实→继续。一般恢复上下文控制在约10000字符内，不能又造一份五万字摘要。若用户当前任务与旧下一步冲突，用户优先。

命令只确认仓库和局部文件，不声称后台进程仍停止、writer仍空、授权仍有效。要写源文件先查实时TaskList/冲突；要动实例先查当前lease/进程和预算，不从旧PID推断。旧授权不会因新会话刷新；金额/调用/墙钟均累计，不退款。

## 维护边界

不自动定时保存、不安装插件、不改宿主压缩阈值；当前实现是项目规则驱动的落盘协议，无法拦截所有突然中断。它解决中断后恢复，不假装能禁止宿主压缩。不要把管理检查点接进NyAiro自己的生活、记忆或状态机。
